## 单一用途

AI Limits 在 Chrome 侧边栏中为你提供一个统一视图，用来跟踪已连接 AI 服务的订阅用量（已用或剩余）、重置时间、消耗节奏和本地用量历史，覆盖二十个受支持的服务（完整名单见支持的服务文档）。基于浏览器会话的服务使用你在浏览器配置中已经登录的账号；基于 API 密钥的服务通过引导流程连接你自己创建的密钥。

## 简短说明

在同一个 Chrome 侧边栏中跟踪已连接 AI 服务的用量、重置时间、消耗节奏和本地历史。

## 详细说明

AI Limits 把你的 AI 订阅用量集中显示在同一个 Chrome 侧边栏中——不必再分别打开多个服务的账号页面，才能确认自己是不是快到限额了。

逐个连接你使用的服务。每个服务都会一目了然地显示各自的用量周期、重置时间、额度和当前套餐。你可以在**已用**和**剩余**之间切换，选择更适合自己的视图。对于同时具备可靠重置时间、以及起始时间或周期时长其中之一的用量周期，AI Limits 会给出消耗节奏，比较已用配额与已经过去的时间。

每个用量周期都可以打开自己的本地历史界面，方便你直接在自己的设备上查看用量随时间的变化趋势。

**ChatGPT** 和 **Claude** 直接从你已登录的账号显示套餐、用量周期、重置时间和可用额度。**Kimi** 直接读取你的用量和订阅状态；如果会话需要刷新，会有一个简短、可见的恢复步骤。**Cursor** 会显示 Cursor 模型与其他模型的月度限额以及 Grok Bot 每周用量，并按 Cursor Models 和 Other Models 分组列出各模型的包含用量（输入、输出、费用和服务商合计）。该明细视图是通用的分服务界面；目前只有 Cursor 会填充它。**Grok** 读取你已登录的消费者版套餐和速率限制窗口。**Mistral** 显示本月至今支出和可用额度，**Perplexity** 显示周期性、已购买和促销额度池。**ElevenLabs** 通过你自己创建的、权限受限的只读 API 密钥连接。**New API** 用你提供的密钥连接自建或第三方 API 兼容实例。AI Limits 支持多个相互独立的 New API 实例，包括同一来源下多个分别标注的密钥。**LiteLLM**、**ClawRouter**、**sub2api** 和 **LLM Proxy** 使用你提供的密钥连接可配置实例。**DeepSeek** 和 **Moonshot** 显示开发平台余额，**DeepInfra** 显示当月支出相对上限的配额或服务商报告的余额，**Fireworks** 显示最近 30 天已计价支出。**OpenAI** 显示组织支出和补全用量并提供额度回退，**GroqCloud** 显示五分钟用量速率，**OpenRouter** 显示额度和可选密钥预算。

AI Limits 的一切数据都保存在本地：你的用量历史只留在你自己的设备上，不会发送到任何别处。没有广告，无需注册 AI Limits 账号，也没有任何分析或遥测。

AI Limits 是 TiantianFlow 独立开发的项目，与任何已连接的服务提供商及其母公司或关联公司均无关联，也未获得它们的认可或授权。

## 权限说明

### 必需权限

- `storage`：在 `chrome.storage.local` 中保存显示和刷新偏好、服务访问状态、标准化后的配额/计数/余额快照、最多 30 天的按类型分实例 History，以及经过清理的刷新状态。它还会在 `chrome.storage.session` 中保存临时的 Kimi 和 Cursor 标签页清理租约元数据。浏览器会话 cookie 和访问凭据不会被持久化。验证通过后，用户创建的服务商 API 密钥会保存在单独的 `chrome.storage.local` 凭据记录中，其 Chrome 存储访问级别仅限于受信任的扩展上下文。该记录不受操作系统钥匙串加密保护，因此从已解锁的 Chrome 配置文件、扩展 DevTools 或配置文件文件中仍可能被检查到。
- `alarms`：仅在启用自动刷新且至少有一个服务已连接时，安排大约每 15 分钟一次的刷新周期。
- `sidePanel`：在 Chrome 侧边栏中显示本扩展的唯一应用界面。

### 可选主机权限

这些来源会在用户点击 **连接** 后按服务逐个请求。安装时不需要其中任何一项。

- `https://chatgpt.com/*`：读取已登录用户的 ChatGPT 会话和用量响应。
- `https://claude.ai/*`：读取已登录用户的 Claude 组织用量响应。
- `https://www.kimi.com/*`：读取 Kimi 用量/订阅响应，并支持有边界的交互式会话访问与恢复流程。
- `https://cursor.com/*`：读取已登录用户的 Cursor 基础用量。仅在 **连接** 或手动 **刷新** 期间，还可以在一个已经打开的精确来源页面中运行捆绑的只读代码；如果当前没有打开的标签页，可能会短暂打开一个非活动用量页，以请求 Grok Bot、额度授予和汇总包含用量 JSON。
- `https://grok.com/*`：读取已登录用户的 Grok 会话、速率限制和订阅响应。这是 grok.com 上的消费者版 Grok，不是 Cursor 的 Grok Bot。
- `https://admin.mistral.ai/*` 和 `https://console.mistral.ai/*`：从已登录的 Mistral 会话读取本月用量和额度。
- `https://www.perplexity.ai/*`：从已登录的 Perplexity 会话读取额度池。
- `https://api.elevenlabs.io/*`：仅在只读订阅请求中，将用户创建的 API 密钥作为 `xi-api-key` 请求头发送，然后标准化每月额度和受支持的语音限制。扩展不会请求 `https://elevenlabs.io/*`；设置页面按普通网页打开，不会获得扩展主机访问权限。
- `https://api.deepseek.com/*`、`https://api.moonshot.ai/*`、`https://api.deepinfra.com/*`、`https://api.fireworks.ai/*`、`https://api.openai.com/*`、`https://api.groq.com/*` 和 `https://openrouter.ai/*`：只会将所选服务已保存的密钥发送到该服务固定的只读余额、用量、指标或账单接口。
- `https://*/*`：用于 New API、LiteLLM、ClawRouter、sub2api 和 LLM Proxy 实例的可选动态主机能力。扩展在运行时绝不会请求此通配符；在网址标准化后，Chrome 只会被请求该实例的精确 HTTPS 来源。
- `http://localhost/*` 和 `http://127.0.0.1/*`：用于本地 New API 开发的可选动态能力。运行时权限仍仅限于用户输入的精确 localhost 来源和端口。公共 HTTP 来源会被拒绝。

### 可选 API 权限

- `cookies`：仅在获得 Kimi 访问权限时请求；在可用时只读取 Kimi 精确的旧版 `kimi-auth` cookie。此项检查发生在读取 Kimi 页面存储之前。
- `scripting`：在获得 Kimi 或 Cursor 访问权限时请求。对于 Kimi，它只从一个已经打开或由恢复流程创建的匹配 Kimi 页面中，读取精确的 `access_token` 浏览器存储条目。如果凭据缺失或被拒绝，交互式恢复可能会创建一个不活动的 Kimi 首页标签页。恢复流程在 10 秒后停止等待凭据，并仅对其自己创建的标签页尝试尽力清理；关闭过程或浏览器 API 错误可能延迟或阻止清理。对于 Cursor，**连接** 或手动 **刷新** 可以在一个已经打开的 `cursor.com` 页面中运行捆绑的精确来源函数。如果当前没有打开的标签页，该交互路径可能会创建一个不活动的 `https://cursor.com/dashboard/spending` 标签页，最多等待 10 秒，并且只关闭它自己创建的标签页。它绝不会激活标签页，也绝不会关闭用户自己打开的标签页。该函数仅向 Grok Bot、额度授予和汇总用量仪表板端点发送固定正文为 `{}` 的 POST 请求，只返回它们的 JSON，并且不会直接检查渲染内容、浏览器存储或 cookie 值。Chrome 会把已登录的 Cursor cookie 附加到这些同源请求。定时刷新绝不会打开标签页或向 Cursor 页面注入代码。

清单不会请求范围更广的 `tabs` 权限。定时刷新不会创建或激活服务标签页，也绝不会向服务页面注入代码。

## 数据披露答案

- **身份验证信息：** 是。这包括用户创建、并在验证成功后由 AI Limits 保存在本地的服务商 API 密钥。其他服务的浏览器会话 JSON、cookie 和访问凭据仅在所选采集序列期间使用，不会被持久化。API 密钥保存在单独的受信任上下文凭据记录中，只发送到所选服务的 API，绝不会发送给开发者。
- **网站内容：** 是。AI Limits 会处理私有的服务会话、用量、订阅和组织响应 JSON，以及 Kimi 精确的 `access_token` 浏览器存储条目和 Cursor 的手动页面上下文仪表板 JSON 响应（Grok Bot、额度授予和汇总包含用量）。它不会读取已渲染的页面文本、提示词、对话或生成的回复。
- **账户标识符和个人身份信息：** 是，但处理范围很窄。从访问凭据派生的 ChatGPT 账户标识，以及 Claude 的组织 UUID/能力信息，仅在请求期间使用，不会被持久化。Claude 的组织名称可能会被标准化并存储为可见的套餐标签。类似电子邮件形态的账户标签会被丢弃，当前适配器不会查询 Claude 或 Cursor 的电子邮件端点。
- **财务和支付信息：** 是，仅限于用量响应中包含的、由服务商报告的用量额度余额、额外用量金额或限额，以及按需支出数值/限额。这些标准化计数和余额可能会保留在本地的分实例 History 中。不会访问或保留支付卡、银行信息、原始服务响应或交易历史。
- **网络历史：** 是，分类范围很窄且偏保守。在 Kimi 采集期间，AI Limits 可能会检查是否已有匹配 Kimi 精确来源的已打开标签页。在 Cursor **连接** 或手动 **刷新** 期间，它可能会检查是否已有一个匹配 Cursor 精确来源的已打开标签页。这只会揭示该固定服务来源的标签页当前是否打开，仅在本地用于所请求的服务操作，绝不会被保留、传输或汇编成已访问页面列表。AI Limits 不会查询任意页面网址、标题或 Chrome 浏览历史。
- **用户活动：** 不会监控点击、按键、指针移动、滚动或一般浏览活动。
- **健康信息、私人通信和位置：** 否。
- **出售或无关共享：** 否。数据不会被出售，也不会发送给开发者、广告商、数据经纪人或无关第三方。
- **分析、广告、遥测或远程后端：** 无。
- **保留与控制：** 成功的标准化配额、计数或支出以及余额观测会按实例保留；History 只绘制配额指标，计数或支出以及余额观测仍会保存但不会绘图。成功的标准化配额、计数/支出以及余额观测会按实例保留在本地 Chrome 配置文件中，最多 30 天，并受每个实例 1,024 条观测的安全上限约束。在该上限内，最近 48 小时的观测保持采集分辨率；更早的保留 History 只保留每个 UTC 小时内的最新值。断开连接会在尽力清理权限之前移除该实例的密钥/配置/用量/History；**删除全部本地数据** 会移除每一个实例，即使某项权限无法撤销。从外部移除权限则保留实例数据和已保存密钥，但将受影响实例标记为需要权限。卸载扩展或清除浏览器存储会删除这些本地记录。用户可以随时关闭自动刷新。被拒绝的 API 密钥会停止该实例的定时请求，过期的标准化用量和 History 会保留到替换或删除为止。
- **用途限制：** 数据仅用于提供用量仪表板、刷新健康状态、权限生命周期和用户请求的设置。不会用于广告、信贷决策或与单一用途无关的目的。

完整政策见[隐私说明（英文）](../../PRIVACY.md)。

## 审核前提条件

- Chrome 116 或更高版本。
- 经过校验的 `ai-limits-0.4.2-chrome.zip` 上传产物。
- 审核人员自有的测试账号，并已在同一 Chrome 配置文件中登录所需的浏览器会话服务站点；还需为待测 API 密钥服务创建临时密钥。ElevenLabs 应使用 **User → Read**。扩展不内置、也不提供任何凭据或服务账号。
- 能够访问各服务来源的网络。私有端点行为和账号权益可能影响哪些用量窗口会显示。
- 仓库公开之后、提交 Chrome 应用商店之前，请在未登录的浏览器中确认主页、隐私政策和支持网址均可访问。

## 二十个服务的测试流程

1. 安装提交的构建，或解压 ZIP 并将其根目录作为未打包扩展加载。如需要可固定 AI Limits，选择其工具栏操作，并确认侧边栏打开后显示二十张需要权限的卡片。
2. **ChatGPT：** 在 `chatgpt.com` 登录，在 ChatGPT 上点击 **连接**，只批准 ChatGPT 来源，并确认出现套餐以及可用的配额窗口或额度。使用该卡片的 **刷新** 操作一次。
3. **Claude：** 在 `claude.ai` 登录，在 Claude 上点击 **连接**，只批准 Claude 来源，并确认出现组织套餐以及可用的用量窗口或额外用量额度。使用该卡片的 **刷新** 操作一次。
4. **Kimi：** 在 `www.kimi.com` 登录，在 Kimi 上点击 **连接**，批准 Kimi 来源以及 `cookies` 和 `scripting`，并确认出现可用用量和订阅数据。如果在交互式刷新期间需要会话恢复，可能会出现一个不活动的 Kimi 标签页。确认恢复流程在 10 秒后停止等待凭据并尝试尽力清理；不要把关闭过程或浏览器 API 错误期间的延迟清理当作保证被违反。
5. **Cursor：** 在 `cursor.com` 登录。**不必**预先打开一个 Cursor 标签页。在 Cursor 上点击 **连接**，并批准 Cursor 来源以及 `scripting`。确认可能会出现 Cursor 模型与其他模型的月度限额、Grok Bot 每周用量，以及按 Cursor Models 和 Other Models 分组的包含用量明细（输入、输出、费用和服务商合计）。如果当时没有已经打开的 `cursor.com` 标签页，可能会出现一个不活动的 `https://cursor.com/dashboard/spending` 标签页，读取后关闭；确认它不会被激活，并且审核人员自己打开的标签页不会被关闭。在已经打开一个 Cursor 标签页的情况下再使用该卡片的 **刷新** 操作一次，确认会复用现有标签页而不会再创建第二个。然后关闭所有 Cursor 标签页并启动一次**定时**周期（或等待自动刷新）：基础的每月/按需用量应仍然可用，不应打开 Cursor 标签页，也不应向页面注入代码。此前采集到的 Grok Bot、额外额度和明细可能作为更早的页面数值继续显示，直到 Grok Bot 的每周重置，并且卡片应说明为何未能刷新。
6. **Grok：** 在 `grok.com` 登录，在 Grok 上点击 **连接**，只批准 Grok 来源，并确认出现 SuperGrok 系列或 Free 套餐以及所报告的查询窗口。使用该卡片的 **刷新** 操作一次。不应再请求额外的 `cookies` 或 `scripting` 权限。
7. **Mistral：** 在 `admin.mistral.ai` 登录，连接 Mistral，仅批准 Mistral 来源，并确认显示本月至今支出和可用额度。记录服务是否接受缺少 `X-CSRFTOKEN` 请求头的请求。
8. **Perplexity：** 在 `www.perplexity.ai` 登录，连接 Perplexity，仅批准该来源，并确认显示周期性、已购买和促销额度池。
